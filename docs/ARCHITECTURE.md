# Architecture

> Canonical system view for the **echo** backend. This document is short on purpose. Detailed rationale lives in [`adr/`](./adr/); execution sequencing lives in [`AGENT_PLAN.md`](./AGENT_PLAN.md); operations live in [`RUNBOOK.md`](./RUNBOOK.md).

## Purpose

Aggregate free OSINT tools (Sherlock, Maigret, Holehe, theHarvester, …) behind a single HTTP API. Each tool becomes a **provider** behind a uniform interface, gaining caching, rate limiting, circuit breaking, cancellation, and live progress streaming for free.

## System shape

### Phase 1 (today) — single VPS

```
                   Cloudflare (DNS + edge cache)
                              │
                              ▼
                  ┌──────────────────────────────────┐
                  │   Hetzner CCX13 (1× VPS, €16/mo) │
                  │                                  │
                  │   Caddy :443  (TLS, IP RL)       │
                  │       │                          │
                  │       ▼                          │
                  │   echo-api      (NestJS)         │
                  │       ├─ HTTP                    │
                  │       └─ SSE                     │
                  │                                  │
                  │   echo-worker   (NestJS, BullMQ) │
                  │                                  │
                  │   echo-osint-py (FastAPI sidecar │
                  │                  with Sherlock,  │
                  │                  Maigret, etc.)  │
                  │                                  │
                  │   Postgres 17                    │
                  │   Redis 7                        │
                  └──────────────────────────────────┘
```

`docker compose up` brings the whole stack online. One image is shared between API and worker (role decided by `APP_ROLE` env).

### Phase 2 — split when needed

Triggers (any of):
- p95 API latency > 400 ms during OSINT bursts
- BullMQ active jobs ≥ worker concurrency × 0.8 sustained
- > 500 concurrent users

Action: peel `echo-worker` and `echo-osint-py` to a second box (CCX13/CCX23). API + Caddy stay; DB + Redis stay or move to a third box. **No code change** — just a different `docker-compose` file pointing at the right host.

### Phase 3 — auth + paywall (deferred)

When the product flips to "lookup → pay → see results":
- Activate `users` + `sessions` (Better-Auth or Lucia, decided then).
- Implement `PaymentProvider` interface (Stripe first; crypto / Privat24 / Monobank / LiqPay added on demand).
- Result endpoints check `lookups.paid_at`; pre-payment, return only `summary`.
- Schema is designed to absorb this — `users.id` and `lookups.user_id` / `lookups.paid_at` are already nullable columns. See [ADR-0012](./adr/0012-no-auth-no-payments-phase1.md).

## Components

### `apps/api` (NestJS)

- HTTP server (Fastify adapter) with global validation pipe (Zod via `nestjs-zod`).
- Controllers: `LookupsController`, `ProvidersController`, `HealthController`, `MetricsController`.
- SSE endpoint for live lookup progress (`GET /api/lookups/:id/stream`).
- Global rate limit (`@nestjs/throttler`) + per-provider quota guard.
- OpenAPI generated by `@nestjs/swagger`, served at `/api/openapi.json`.
- Structured logs via `nestjs-pino`; OpenTelemetry traces via SDK + auto-instrumentations.
- No business logic in controllers — they delegate to services in `packages/`.

### `apps/worker` (NestJS, no HTTP)

- Same Nest application but bootstrapped in `APP_ROLE=worker` mode.
- Hosts BullMQ consumers (`@nestjs/bullmq`), one queue per provider (`q.<providerId>`).
- Pulls jobs, resolves the provider from the registry, runs it, writes events to Postgres and to Redis Streams.
- Honors cancellation signals (Redis pub/sub) by aborting in-flight work.
- Same OpenTelemetry / logging setup as the API; trace context flows through job options.

### `services/echo-osint-py` (Python sidecar)

- FastAPI service in `services/echo-osint-py/`.
- Hosts every Python-only OSINT tool we use (Sherlock, Maigret, Holehe, theHarvester, PhoneInfoga, …).
- One process, one image — amortizes Python startup and dependency weight.
- Endpoints: `POST /providers/<id>/run` returns SSE; `GET /providers/<id>/info` returns metadata.
- Optional proxy pool (round-robin) for tools that scrape.
- See [ADR-0008](./adr/0008-python-osint-sidecar.md) for the rationale.

### `packages/`

Shared workspace packages. Each is independently typecheckable and unit-testable.

| Package | Responsibility |
|---|---|
| `@echo/contracts` | Zod schemas + TS types shared across api + worker (DTOs, BullMQ payloads, provider IO). |
| `@echo/db` | Drizzle schema, migrations, repository functions. Owns the Postgres connection pool. |
| `@echo/providers` | `OsintProvider` interface, registry, conformance test suite, every provider implementation in subdirs. |
| `@echo/queue` | BullMQ wiring + per-provider queue config. Provides `@nestjs/bullmq` modules to the worker. |
| `@echo/cache` | Redis client + multi-tier cache + single-flight lock. |
| `@echo/http-clients` | Pre-configured outbound HttpClients with retry/timeout/breaker policies per provider. |
| `@echo/observability` | OpenTelemetry SDK setup, `nestjs-pino` config, Prometheus metric helpers. |
| `@echo/config` | Env schema (Zod), strongly typed `ConfigService`. |
| `@echo/testing` | Testcontainers helpers, factory builders for fixtures, in-memory provider stubs. |

## Data model (canonical)

Source of truth is the Drizzle schema in `packages/db/src/schema/`. Sketch:

| Table | Key columns | Purpose |
|---|---|---|
| `lookups` | `id` (uuid), `provider_id`, `query_hash`, `query` (jsonb), `status`, `result` (jsonb), `error_kind`, `error_message`, `ip_address`, `user_id` (nullable), `paid_at` (nullable), `created_at`, `started_at`, `finished_at` | One row per OSINT request |
| `lookup_events` | `id`, `lookup_id`, `seq`, `payload` (jsonb), `created_at` | Append-only progress events; durable history mirrored from Redis Streams |
| `providers` | `id`, `enabled`, `breaker_state` (closed/half_open/open), `breaker_opened_at`, `last_success_at`, `last_failure_at` | Runtime state per provider; persisted so breaker survives worker restarts |
| `users` *(empty in Phase 1)* | `id`, `email`, `created_at`, … | Reserved for Phase 3 |
| `payments` *(empty in Phase 1)* | `id`, `user_id`, `provider`, `status`, `amount_cents`, `currency`, … | Reserved for Phase 3 |

Indexes called out:
- `lookups (provider_id, query_hash)` — supports cache lookup + idempotency.
- `lookups (created_at DESC)` — recent activity views.
- `lookup_events (lookup_id, seq)` — replay in order.

## Request flow — start a lookup

```
POST /api/lookups { providerId, query }

  ① API validates body against provider.inputSchema.
  ② API canonicalizes query → queryHash = sha256(canonical).
  ③ API: cache.get("result:<providerId>:<queryHash>")
        ─ HIT: return 200 { id, cached: true, result }
        ─ MISS: continue
  ④ API: insert lookups row (status=queued); jobId = lookups.id.
  ⑤ API: bullQueue<providerId>.add(jobId, { lookupId, query })
        with single-flight Redis lock keyed by queryHash.
  ⑥ API: return 202 { id, streamUrl: "/api/lookups/:id/stream" }
```

## Request flow — stream progress (SSE)

```
GET /api/lookups/:id/stream
Last-Event-ID: <optional, for reconnect>

  ① API: subscribe to Redis stream "lookup:events:<id>" (consumer group per connection).
  ② Worker, in parallel:
       - pulls BullMQ job
       - resolves provider from registry
       - calls provider.run(query) — receives an async iterable of ProviderEvents
       - per event: append to lookup_events (Postgres) + xadd to Redis stream
       - on Final: lookups.status=done, write result to lookups.result
  ③ API forwards each Redis-stream entry to the SSE client as `data: {...}`.
  ④ On Final, API closes the SSE connection.
  ⑤ If client disconnects mid-stream, the job continues.
       Reconnect with Last-Event-ID replays missed events from the Redis stream history (TTL 1h).
```

## Request flow — cancel

```
DELETE /api/lookups/:id

  ① API: lookups.status=cancelled (only if currently queued|running).
  ② API: redis.publish("lookup:cancel:<id>", "1")
  ③ Worker observes the publish; calls AbortController on the in-flight provider.run().
  ④ Worker writes a final event { _tag: "Cancelled" } to lookup_events + Redis stream.
```

## The OSINT provider abstraction

The single most load-bearing piece of code. Defined in `packages/providers/src/core/`.

```ts
export interface OsintProvider<Q = unknown, R = unknown> {
  readonly id: string                       // "sherlock", "holehe", ...
  readonly category: ProviderCategory       // "username" | "email" | "phone" | "domain" | ...
  readonly inputSchema: ZodType<Q>
  readonly outputSchema: ZodType<R>
  readonly defaults: {
    timeoutMs: number
    maxConcurrent: number
    cacheTtlSec: number
    breaker: { failureThreshold: number; resetMs: number }
  }
  run(query: Q, ctx: ProviderRunContext): AsyncIterable<ProviderEvent<R>>
}

export type ProviderEvent<R> =
  | { readonly _tag: "Started" }
  | { readonly _tag: "Progress"; readonly pct: number; readonly note?: string }
  | { readonly _tag: "Partial"; readonly chunk: unknown }
  | { readonly _tag: "Final"; readonly data: R }
  | { readonly _tag: "Cancelled" }
```

Cross-cutting concerns wrapped around every provider by `@echo/providers/core`:
- **Cache**: query → result by `(id, sha256(canonicalize(q)))` with provider-defined TTL.
- **Single-flight**: identical concurrent queries collapse to one upstream call.
- **Concurrency cap**: dedicated BullMQ queue per provider with `defaults.maxConcurrent` workers.
- **Circuit breaker**: state persisted in `providers` table; opens after N failures, half-opens after M ms.
- **Rate limit**: token bucket per provider on the outbound HttpClient.
- **Cancellation**: `AbortSignal` propagated from API → BullMQ → provider implementation.
- **Tracing**: spans tagged `provider.id`, `provider.category`, `lookup.id`.
- **Conformance test**: every provider must pass a parameterized test suite (input schema validates known good/bad payloads; cancellation works mid-stream; output decodes a canned response).

See [ADR-0005](./adr/0005-osint-provider-abstraction.md).

## Cross-cutting concerns

### Caching (multi-tier)

| Layer | Storage | TTL | Purpose |
|---|---|---|---|
| L1 | In-process LRU | 10 s | Hot lookup IDs |
| L2 | Redis | per-provider (1 h – 7 d) | Result cache |
| L3 | HTTP `Cache-Control` | from L2 TTL | Edge / browser cache |
| Lock | Redis `SET NX PX` | 30 s | Single-flight |
| Stream | Redis Streams | 1 h after Final | SSE replay window |

See [ADR-0009](./adr/0009-cache-strategy.md).

### Rate limiting (Phase 1 = anonymous public)

1. **Edge** — Caddy per-IP burst + global RPS ceiling.
2. **CDN** — Cloudflare WAF + bot fight.
3. **API** — `@nestjs/throttler` per IP (Redis-backed); 10 lookups / hr / IP unauthenticated.
4. **Per-provider concurrency** — BullMQ queue concurrency = `provider.defaults.maxConcurrent`.
5. **Per-provider breaker** — opens on consecutive failures; surfaced as `503 Service Unavailable`.
6. **Backpressure** — when waiting count > N, `POST /api/lookups` returns `503 + Retry-After`.
7. **Cost guard** — per-provider daily call counter; alert on threshold.
8. **Captcha gate** — Cloudflare Turnstile prompt when per-IP threshold breached.

See [ADR-0010](./adr/0010-rate-limiting-without-auth.md).

### Observability

- **Logs**: `nestjs-pino` → JSON to stdout → Docker → Grafana Cloud Loki (free tier) [optional].
- **Traces**: OpenTelemetry SDK + auto-instrumentations for HTTP, Postgres, Redis, BullMQ. Exported via OTLP.
- **Metrics**: queue depths, cache hit ratio, per-provider success rate, breaker state — all exposed at `/api/metrics` (Prometheus exposition).
- **Health**: `/api/health/live` (process up) and `/api/health/ready` (Postgres + Redis + sidecar reachable).

### Security posture

Out of scope for Phase 1 detailed in [ADR-0012](./adr/0012-no-auth-no-payments-phase1.md). Posture today:
- Public unauthenticated read+write — abuse mitigated by rate limiting.
- All secrets via env (12-factor); never committed.
- Container base images pinned to digests; renovate-bot updates.
- Caddy enforces TLS; HSTS on; basic security headers.
- Postgres + Redis only listen on the Docker network — never exposed publicly.
